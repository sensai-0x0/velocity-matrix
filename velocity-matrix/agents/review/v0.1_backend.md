## 2. Completion Phases (ordered)

### Phase B0 — Deploy prerequisites (block everything else)

1. Copy `.env.example` → `.env`; set `GITHUB_PAT`, `LLM_API_KEY`, `SLACK_BOT_TOKEN`, `SLACK_CHANNEL_ID`.
2. Enable GitHub (or Google) login in `base44/auth/config.jsonc` once Base44 dashboard SSO/secrets exist; keep email/password only as local fallback.
3. Run `bun run deploy` (or `npx base44 deploy -y`) and confirm entities + three functions appear in the Base44 dashboard.
4. Smoke: authenticated `invoke('process-voice-command', …)` creates an `ActiveBlockers` row with `owner_id === user.id`.

**Exit criteria:** Deploy succeeds; RLS isolates rows; secrets resolve in Deno (`Deno.env.get`).

---

### Phase B1 — Close the Node 01 → Node 02 synapse (critical path)

**Gap:** Ingestor inserts `ActiveBlockers` then returns. Synthesizer only runs if something invokes it. AGENTS.md Node 02 trigger is *Database Webhook INSERT on ActiveBlockers*.

1. Register a Base44 database webhook (or `base44` automation) on `ActiveBlockers` **INSERT** → `functions.invoke('synthesize-solution', { blocker_id })`.
2. Confirm webhook payload shape matches `resolveBlockerId()` (`blocker_id` | `record.id` | `data.id`).
3. Optionally: from Node 01, fire-and-forget `base44.functions.invoke('synthesize-solution', { blocker_id })` as a dual-path until webhook is reliable (document as temporary; prefer webhook for AGENTS.md fidelity).
4. After success path, ensure UI can observe:
   - row updates: `status`, `completion_percentage`, `current_focus`, `latency_ms`
   - new `GeneratedSolutions` row with full ResolutionArtifact fields

**Exit criteria:** One voice ingest → telemetry steps 0→100 → `GeneratedSolutions` row without manual invoke.

---

### Phase B2 — Auth cell provisioning

**Gap:** Solo-Cell unlock requires a `HackathonState` row; nothing creates it today.

1. Add Edge function (or auth-hook) `provision-hackathon-state`:
   - On first `auth.me()` / login, if `HackathonState.list()` empty → `create({ owner_id, session_id, current_focus_area, last_active_timestamp })`.
2. Accept optional `target_repo_url` from onboarding UI later; Executor already fails closed without it.
3. Keep Rule A: never trust client `owner_id` / `hacker_id`.

**Exit criteria:** New user gets exactly one `HackathonState` cell; subsequent logins no-op.

---

### Phase B3 — Harden Node 01 (Ingestor)

| Item | Action |
|------|--------|
| `hacker_id` in contract | Keep optional or drop from required client payload; never persist client value. Align `isValidPayload` with UI (session_id, timestamp_ms, transcript, urgency_flag). |
| Context tags | Derive from transcript keywords (or light LLM) so ingestion evals / UI tags are real, not always `[]`. |
| Urgency | Optionally derive server-side if client omits / lies (`blocker`, `urgent`, `ASAP`). |
| Session continuity | Document that multiple blockers share `session_id`; do not invent a new session per utterance. |

**Exit criteria:** Ingestion evals pass against live function (or tighter mock parity).

---

### Phase B4 — Harden Node 02 (Synthesizer)

| Item | Action |
|------|--------|
| InvokeLLM response shape | Confirm SDK returns object vs `{ text }` / string; harden `parseLlmResponse` for all three. |
| Connector routing | Prefer `llm_reasoning_core` / manifest config over generic `Core.InvokeLLM` if Base44 requires named connector. |
| Degraded retry | On `LLM_TIMEOUT` / `429`, leave `is_resolved: false` + `current_focus: Queued for retry`; add scheduled re-invoke or client-driven retry (document chosen path). |
| `JobStatus` | Architecture doc mentions JobStatus; **do not add a fourth entity** unless required — keep degraded state on `ActiveBlockers`. |
| Status finalization | After artifact write, consider a terminal status or rely on `is_resolved: true` + `completion_percentage: 100` (document for UI). |

**Exit criteria:** Synthesis eval suite green on schema adherence; timeout/429 never crash the HTTP loop (already returns 200).

---

### Phase B5 — Complete Node 03 (Executor)

| Item | Action |
|------|--------|
| `cli_executor` | Implement or reject with explicit `error_trace: "cli_executor not enabled in v0.1"`. Prefer implement minimal Deno shell only if Base44 permits; otherwise document GitHub-only for v0.1. |
| Connector vs raw fetch | Prefer `github_auto_commit` connector action when available; keep Contents API fallback (current). |
| Branch targeting | Make branch configurable via `HackathonState` (default `main`). |
| Discard semantics | Optionally soft-delete / mark discarded so UI can hide the node. |
| Slack | Treat notify failure as non-fatal (already); assert channel env in validate when Slack enabled. |

**Exit criteria:** Deploy → commit URL in `ExecutionResult.deployment_url` + `has_been_committed: true`; Override uses `modified_code`.

---

### Phase B6 — Security & evals gate

1. Run `bun run evals:run` in CI / pre-deploy (`init_matrix.sh` Phase 5 already intends abort-on-fail).
2. Add one **live** RLS probe: forged JWT / second user cannot read another cell (or document mock-only until Base44 test tokens exist).
3. Latency smoke: INSERT → first `ActiveBlockers` update `< 400ms` where measurable.
4. Re-run `bun run validate` after any schema/manifest change.

**Exit criteria:** Eval runner exits 0; zero-trust denial messages match `MATRIX_DENIED` vocabulary.

## 3. Out of Scope for Backend v0.1

- Multi-branch / PR-based commits
- AST compilation of LLM code inside Deno (eval concern only)
- Separate `JobStatus` table
- Raw `fetch` to Postgres (forbidden — keep SDK)
- Bypassing RLS except documented service-role connector token fetch
